# Ponytail Rules — Janoon

> Lazy senior developer mode. Efficient, not careless.
> Adapted from [DietrichGebert/ponytail](https://github.com/DietrichGebert/ponytail) (MIT).

---

## The Ladder — stop at the first rung that holds

1. **Does this need to exist?** Speculative need = skip it, say so in one line. (YAGNI)
2. **Already in this codebase?** A helper, util, type, or pattern that already lives here → reuse it. Look before writing — re-implementing what's a few files over is the most common slop.
3. **Stdlib does it?** Use it.
4. **Native platform feature covers it?** `<input type="date">` over a picker lib, CSS over JS, DB constraint over app code.
5. **Already-installed dependency solves it?** Use it. Never add a new one for what a few lines can do.
6. **Can it be one line?** One line.
7. **Only then:** the minimum code that works.

> The ladder is a reflex, not a research project — but it runs *after* you understand the problem, not instead of it.

---

## Rules

- **No unrequested abstractions:** no interface with one implementation, no factory for one product, no config for a value that never changes.
- **No boilerplate, no scaffolding "for later"** — later can scaffold for itself.
- **Deletion over addition.** Boring over clever.
- **Fewest files possible.** Shortest working diff wins — but only once you understand the problem.
- **Complex request?** Ship the lazy version and question it: *"Did X; Y covers it. Need full X? Say so."*
- **Two stdlib options, same size?** Take the one that's correct on edge cases.
- **Mark deliberate simplifications** with a `ponytail:` comment naming the ceiling and upgrade path.

## Bug Fixes

Fix the root cause, not the symptom. Before editing, grep every caller of the function you're about to touch. One guard in the shared function is a smaller diff than a guard in every caller.

## Output

Code first. Then at most three short lines: what was skipped, when to add it.
Pattern: `[code] → skipped: [X], add when [Y].`

## When NOT to be lazy

Never simplify away: input validation at trust boundaries, error handling that prevents data loss, security measures, accessibility basics, anything explicitly requested.

Never lazy about understanding the problem. Read the full flow before picking a rung. Laziness that skips comprehension to ship a small diff is the dangerous kind.

## Project-Specific Overrides

These are specific to the Janoon codebase and take priority over generic rules above.

### Design Lock
- **Do not alter** existing UI polish, dark-mode styling, component layouts, or the established aesthetic.
- All new logic goes inside the existing design system — Tailwind + shadcn/ui + Framer Motion.

### Supabase-First
- All persistence goes through Supabase (`src/lib/supabase.ts`).
- Every new feature that needs data must provide its `CREATE TABLE` schema in `supabase/schema.sql`.
- Use `src/lib/db.ts` for data operations and `src/hooks/use-live-db.ts` for realtime subscriptions.
- Reads must never throw — return `[]` on failure. Mutations throw with actionable messages.

### Existing Code Before New Code
- Reuse existing components from `src/components/tribe/` or `src/components/admin/` before creating new ones.
- Reuse hooks from `src/hooks/` — especially `useLiveSite`, `useLiveTable`, `useStaffAuth`, `useCart`.
- Reuse utilities from `src/lib/` — `formatRupees`, `mediaUrl`, `cn`, `RESTAURANT` constants.

### Convex Is Retained
- Convex (`src/convex/`) is kept for customer sign-in (`/auth` → `/restaurant`).
- Do not add new Convex functions for data operations — use Supabase.

### Staff & Admin Auth
- Supabase Auth is the only identity source for the portals (`src/hooks/use-staff-auth.ts`).
  There is no PIN and no localStorage session — do not reintroduce either.
- The role comes from a `staff_members` row keyed by the Supabase auth UUID, never from
  the client: `role === "admin"` alone opens `/admin`, `staff` or `admin` open `/staff`
  (`src/components/RequireRole.tsx`).
- The first admin account is created on the website, not in the dashboard: sign up in the
  Admin Portal card (First-time setup) and `claim_admin()` records the UUID. That function
  only ever fires while `staff_members` is empty, so the door is one-time.
- Further staff are added from the SQL editor — the one place that can hold a credential
  powerful enough to grant a role. No service-role key may ever reach the bundle.

### File Organization
- Public-facing components: `src/components/tribe/`
- Admin-specific components: `src/components/admin/`
- Pages: `src/pages/`
- Data layer: `src/lib/db.ts`
- Realtime hooks: `src/hooks/use-live-db.ts`
- Schema: `supabase/schema.sql`

### Styling Conventions
- Tailwind CSS only — no inline styles except for Framer Motion's `animate`.
- Use `cn()` utility for conditional classes.
- Dark-mode palette: slate/stone backgrounds, gold/amber accents, ember highlights.
- Responsive mobile-first, `sm:` and `lg:` breakpoints.
